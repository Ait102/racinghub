# Поддержка Racing Hub (этап 7 SDLC)

## Что проверяется автоматически

| Что                                                                                               | Когда                                  | Где                                                          |
| ------------------------------------------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------ |
| Линтер, unit- и E2E-тесты, сборка, публикация на GitHub Pages (только для публичного репозитория) | каждый пуш в `main`                    | `.github/workflows/ci.yml`                                   |
| Живой API Jolpica: доступен ли, не изменился ли формат JSON                                       | каждый понедельник 06:00 UTC и вручную | `.github/workflows/api-health.yml` → `npm run test:contract` |

Если еженедельная проверка падает, в репозитории автоматически открывается issue «API Jolpica: проверка не прошла» со ссылкой на лог. Повторные сбои добавляются в тот же issue комментариями.

Запустить проверку вручную: **Actions → API health check → Run workflow**, или локально:

```bash
npm run test:contract
```

## Если проверка упала

1. Откройте лог из issue и посмотрите, какая проверка не прошла. Сообщения написаны по-русски: например, «маппер отбросил часть этапов — формат календаря изменился».
2. **HTTP 5xx, тайм-аут или сеть** — скорее всего, временный сбой Jolpica. Перезапустите проверку через пару часов. Сайт в это время показывает сохранённые данные с предупреждением.
3. **HTTP 429** — лимиты стали строже. См. раздел «Лимиты».
4. **«Маппер отбросил…» или «не разобраны»** — изменился формат JSON. Сравните ответ API с разбором в `src/series/f1/domain/mappers.ts`, поправьте маппер, добавьте unit-тест на новый формат.
5. Проверьте новости API: https://github.com/jolpica/jolpica-f1 (Releases, Discussions).
6. Закройте issue после исправления.

## Стиль кода

- **ESLint** (`npm run lint`, конфиг `eslint.config.js`): рекомендованные правила JS и TypeScript, правила хуков React, `import type` для типов, строгое сравнение.
- **Prettier** (`npm run format`, конфиг `.prettierrc.json`): одинарные кавычки, точка с запятой, ширина 110, сортировка импортов — сначала React и пакеты, затем модули проекта от дальних к ближним.
- Сгенерированные файлы (`src/series/f1/data/circuits/map.ts`, `shapes/`) форматтер и линтер не трогают.
- CI проверяет и то, и другое: `npm run lint` и `npm run format:check`. Перед коммитом достаточно `npm run format && npm run lint`.

- правя элемент, сначала ищите его селектор в 05–09 — скорее всего, итоговый вид задан там;

## Секреты и .env

Файлы `.env` и `.env.*` в git не попадают (`.gitignore`), шаблон без значений можно хранить как `.env.example`.
Помните: всё, что Vite отдаёт в браузер (`import.meta.env.VITE_*`), видно любому посетителю. Ключи API во фронтенд не кладём — если источник потребует ключ, нужен серверный прокси.

## Лимиты API

Сейчас без токена: 4 запроса/с, 500 запросов/ч. Jolpica предупреждает, что лимиты будут снижаться.
В коде:

- `minIntervalMs` при создании клиента в `src/series/f1/api/jolpica.ts` — минимальная пауза между запросами (сейчас 300 мс ≈ 3,3/с, с запасом до лимита);
- `retries`, `retryBaseMs`, `maxRetryWaitMs` в `src/api/client.ts` — автоповтор при 429 и сбоях;
- `ttlMs` — сколько держать ответ в кэше (по умолчанию 10 минут, задаётся там же, значение по умолчанию — в `src/api/client.ts`). Увеличение кэша — первый способ уменьшить нагрузку;
- самая тяжёлая страница — «График»: по одному запросу на каждый завершённый этап.

Если Jolpica введёт токены, ключ нельзя класть во фронтенд (требование ТЗ) — понадобится серверный прокси.

Сколько запросов тратят страницы (без кэша): профиль пилота — около 10 плюс по одному на каждый сезон его карьеры, сравнение — то же для двух пилотов, «График» — по одному на этап. Итоги **прошедших** сезонов не меняются, поэтому после первой загрузки они берутся из сохранённой в браузере копии без запроса (`immutable` в `src/api/client.ts`); кнопка «Обновить» всё равно идёт к источнику. История команды по сезонам и список всех её пилотов грузятся только по кнопке.

При ответе 429 («слишком много запросов»), сетевой ошибке, таймауте или HTTP 5xx клиент сам повторяет запрос до 3 раз с паузой 1 → 2 → 4 с и придерживает всю очередь. Если источник просит ждать дольше 20 с (исчерпан часовой лимит), повтора нет — показывается ошибка. Сезоны, не загрузившиеся с первого прохода, запрашиваются ещё раз автоматически.

## Схемы трасс

Контуры трасс, длина, число поворотов, направление движения и годы, в которые конфигурация использовалась, — статические данные из [F1DB](https://github.com/f1db/f1db) (CC BY 4.0), не из API.

Устроено так:

- `scripts/build-circuits.mjs` выкачивает YAML и SVG из F1DB и пишет `src/data/circuits/map.ts` (Jolpica `circuitId` → slug F1DB) и `src/data/circuits/shapes/<slug>.ts` — по файлу на трассу, в каждом все её конфигурации с годами (`eras: [[1997, 2009], …]`, `9999` означает «по сей день»). Экспорты по старым путям F1 сохранены; WEC обращается к общим данным напрямую.
- `loadCircuit(circuitId, season)` подтягивает нужный файл через `import.meta.glob` (каждая трасса — отдельный чанк 1–12 КБ) и возвращает конфигурацию, действовавшую в этом сезоне.
- Нет трассы в маппинге, нет конфигурации на этот год или год подходит сразу к нескольким — блок «Схема трассы» не показывается вовсе.

Добавить трассу: строку `'jolpica_id': 'f1db-slug'` в `MAP`, затем

```bash
node scripts/build-circuits.mjs
npm test && npm run build
```

`src/series/f1/components/CircuitMap.test.tsx` проверяет, что геометрия есть для всех трасс сезона и что для разных сезонов выбираются разные конфигурации (Монца 1950 / 1955 / 2026, Сильверстоун 1998 / 2012).

### Чего нет и почему

**Номера поворотов и сектора.** В открытых источниках с явной лицензией их нет: официальные схемы Formula 1 закрыты, F1DB даёт только контур и число поворотов, GeoJSON-наборы bacinger и TUMFTM — только геометрию.

Пробовали выводить из геометрии: считали знаковую кривизну вдоль контура (2400 точек, несколько окон сглаживания и порогов) и выделяли участки поворота. Совпадения с официальным числом — 42 из 158 конфигураций в лучшем наборе параметров, а на крупных трассах детектор ошибается вдвое: Монца 22 против 11, Сильверстоун 36 против 18, Спа 38 против 19, Монако 44 против 19. Это шум рисованной геометрии. Сектора «по третям круга» тоже были бы выдумкой: границы S1/S2/S3 у каждой трассы свои.

Чтобы это появилось, нужен выверенный справочник координат поворотов (ручная разметка по официальным схемам либо источник с явной лицензией) и поле под него в `CircuitLayout`. До этого блок сознательно остаётся без номеров.

**Трассы, которых нет в F1DB** (например, Сочи), схему не показывают — источника геометрии для них нет.

## Исправления результатов

Источник сам обновляет результаты после протестов и штрафов. Приложение подхватывает изменения максимум через 10 минут (кэш) или сразу по кнопке «Обновить».
Раз в несколько этапов повторяйте сверку с formula1.com, как описано в `docs/TESTING.md`.

## Ошибки от пользователей

Принимаются через GitHub Issues. При разборе: какой сезон и страница, что показано на сайте и что ожидалось, совпадает ли это с ответом API (ссылка «Источник» под каждым блоком данных).

## Фото пилотов и болидов

Фото берутся с Wikimedia Commons прямо в браузере (`src/api/wikimedia.ts`), их не надо хранить в репозитории. У пилотов проверяются изображения инфобокса и главное изображение статьи. Допустимы JPEG и подтверждённые фотографические PNG/WebP; графика и несвободные файлы отсекаются. Запросы проходят через существующий HTTP-клиент с очередью, тайм-аутами и повтором при 429. Ответы кэшируются на 7 дней; формат кэша фото — `racinghub:wm:v3:`.

Команды F1 сезона 2026 — болиды из `src/series/f1/data/carPhotos.ts` (серия с Гран-при Австрии 2026, Lukas Raich, CC BY-SA 4.0). Для команд WEC все модели берутся из заявки сезона. Варианты модели, даже с одной статьёй, хранятся отдельно; фотография выбирается по названию модели и варианта в подписи, имени файла или разделе. Дорожная версия не подставляется вместо гоночной. Фото может показывать другую команду или год той же модели — это поясняется на странице. Под фото подписаны автор и лицензия. Если соответствие или лицензия не подтверждены, фото отсутствует, остальные данные продолжают работать.

На новый сезон обновите `carPhotos.ts`: имена файлов новых болидов можно найти в статьях о них в Википедии.

## WEC и Википедия

Данные WEC берутся из английской Википедии (`src/series/wec/api/wikipedia.ts`): у статьи сезона читаются только разделы «Calendar/Schedule» и «Results and standings», статья гонки — целиком. Разбор (`src/series/wec/domain/parse.ts`) ищет колонки по названиям заголовков, поэтому переставленные колонки ему не страшны. Прошедшие сезоны сохраняются в браузере навсегда, текущий — на 10 минут.

Если еженедельная проверка источников (`npm run test:contract`) упала на WEC:

1. Откройте статью сезона и посмотрите, что поменяли: название раздела, заголовки колонок, раскладку таблицы.
2. Скачайте свежий HTML раздела и обновите фикстуры в `src/series/wec/__fixtures__/` (это урезанные настоящие статьи).
3. Поправьте разбор так, чтобы проходили и старые, и новые фикстуры, — старые сезоны в Википедии не переписывают.

Новый сезон появляется сам: список сезонов (`src/series/wec/data/seasons.ts`) доходит до текущего года.

Профили WEC (этап 2): `domain/profiles.ts`, `pages/WecProfilePage.tsx`. Одна статья даёт историю пилота/команды или победителей гонки; зачёт выбранного сезона читается отдельно. Кэш статей профиля ограничен 10 минутами и не использует `immutable` старого сезона. Списки участников (`domain/participants.ts`) читают раздел Entries, включая строки экипажа с `rowspan`; на них не нужна публикация результатов.

Если профиль пуст: проверьте наличие нужного раздела и таблицы в статье, а не добавляйте предположительные данные. У AF Corse история неполная, у Спа таблица Winners без классов. Победы и подиумы в классе считаются только для Ле-Мана по отдельной колонке Class Pos.; места из таблицы WEC нельзя автоматически считать местами в классе. У трассы источник истории — статья гонки (`eventArticle` из календаря), источник фото — статья трассы.

Обновить реальные фикстуры профилей и заявок: `node scripts/fetch-wec-profiles.mjs` (нужна сеть), затем `npx prettier --write src/series/wec/__fixtures__`. Скрипт сохраняет источник, лицензию и дату получения, отправляет User-Agent RacingHub. После обновления запустите unit, E2E и контракт; не подгоняйте данные под тесты.

Сравнение WEC: `pages/WecComparePage.tsx` и `domain/compare.ts`, `compare?a=…&b=…`. Выбор — из Entries, история — из двух статей пилотов через существующий `getProfile`. Никакого обхода всех сезонов и суммирования очков. При изменении разметки сначала обновите проверки на реальных профилях Буэми и Кобаяси; сохраняйте несколько строк сезона и исходный текст места/очков. Не заменяйте отсутствие строки утверждением «не выступал». Проверки страницы — `e2e/wec-compare.spec.ts`, живое сравнение — в контракте Википедии. График мест, избранное, эмблемы и галерея машин уже реализованы.

Основные сведения о пилоте (`facts`, `biography`, `photoFiles`) разбираются вместе с историей из той же статьи. Скрипт обновления фикстур сохраняет основной инфобокс и первый абзац; отдельная настоящая фикстура `driver-buemi-intro.html` закрепляет личные сведения, факты WEC, скрытые даты и портрет. Биография выводится как обычный текст на языке источника.

### Карты WEC и график

`src/series/wec/data/circuits.ts` сопоставляет статьи с трассами и выбирает конфигурацию для WEC отдельно от F1. Общий компонент — `src/components/CircuitMap.tsx`. Нельзя выбирать схему только по последнему году F1: Фудзи, Бахрейн и Имола имеют явные правила WEC; вариант шиканы Нюрбургринга отличается. Снимок проверенных конфигураций ограничен 2026 годом. Новые годы нужно сверять с источником перед расширением.

Ле-Ман с 2018 года и современный Себринг используют отдельные контуры © OpenStreetMap contributors через закреплённую версию track-atlas, ODbL 1.0. `node scripts/build-wec-circuits.mjs` восстанавливает `circuit-shapes.generated.ts`; источник геометрии, лицензия и преобразование масштаба подписаны под схемой. Неподтверждённая историческая конфигурация не заменяется похожей. Сведения о трассах имеют ссылки и дату проверки.

График мест использует общие `src/lib/places.ts` и `src/components/PlacesChart.tsx`, стили WEC — `15-wec-chart.css`. Старые пути WEC сохраняют совместимые экспорты. Разные машины сохраняются; объединение имён пилотов требует совпадения команды, опубликованного места, очков и результатов. Ноль и нечисловые результаты дают разрыв, исходный текст остаётся в деталях. Проверьте Топ-10 на 375 px, касание, стрелки, Home/End и Escape.

Новая страница источников WEC — `#/wec/:season/about`; навигация и footer должны сохранять серию. Снимки README обновляются вместе с визуальными эталонами при `CAPTURE_DOCS=1` (см. `docs/TESTING.md`); не запускайте одновременно два Playwright-прогона с общей папкой результатов.

## Общая основа Википедии и Formula E

- `src/api/wikipedia.ts` — общий клиент MediaWiki, очередь, повтор при 429, кэш, URL и метаданные статей, поиск разделов. WEC сохраняет собственную загрузку сезона и гонки в `src/series/wec/api/wikipedia.ts`. При переносе нельзя менять ключи и правила кэша WEC; завершённые сезоны остаются `immutable`.
- `src/lib/wikiStandings.ts` — общий разбор зачётов, колонок этапов и цветов. Особенности серии задаются параметрами; очки не пересчитываются, строки машин не суммируются. `src/lib/wikitable.ts` по-прежнему раскрывает `rowspan`/`colspan`.
- `src/lib/places.ts` и `src/components/PlacesChart.tsx` — общие модель и отображение мест в гонках. Не превращайте график в вычисленный зачёт чемпионата.
- `src/series/fe/data/seasons.ts` — сезоны с 2014–15, названия статей и определение прошедшего сезона. До 2019–20 статья называется `Formula E Championship`, с 2020–21 — `Formula E World Championship`.
- `src/series/fe/pages/index.ts` — отдельная лениво загружаемая часть FE; маршруты, меню и выбор сезона подключены в `App.tsx` и `Layout.tsx`. Этап 1 подключает главную, календарь, протоколы, квалификацию, зачёты и источники; участники и сравнение пока остаются пояснением этапа 2.
- FE использует `16-fe.css`, токен `--fe-purple` и CSS-классы с приставкой `fe-`. Серии не импортируют друг друга; зависимости общего кода от серий также запрещены ESLint.

FE: `api/wikipedia.ts`, `domain/season.ts`, `domain/race.ts`, `domain/status.ts`. В первом сезоне результаты и зачёты — отдельные разделы. При изменении таблиц сначала обновите настоящие фикстуры командой `node scripts/fetch-fe.mjs`, затем проверки на 2014–15, 2019–20 и 2025–26 и одиночные/сдвоенные протоколы. Скрипт сохраняет источник, дату и лицензию; запросы подписаны User-Agent проекта. Живые проверки FE находятся в `src/series/fe/contract/` и входят в общий контрактный прогон; не повторяйте их часто при HTTP 429.

Общий `wikiStandings` имеет режим FE: ищет колонку Pts независимо от лишнего colspan в подвале, сохраняет номера обеих машин и исходный текст пометок. Для графика отдельно сохраняется числовое место без надстрочных пометок. Режим WEC сохраняет прежнее поведение. Статус «Завершён» требует опубликованного победителя; часы старта не достраиваются. Отсутствующая статья сезона даёт пустое состояние, сетевой сбой — ошибку с повтором.

Избранное FE — `hooks/favorites.ts`, отдельный ключ `racinghub:fe:favorites`; используется в зачётах и на главной. Следующие этапы: участники/профили/сравнение (2), эмблемы/фото/оформление (3). План — `docs/FORMULA-E-PLAN.md`, состояние — `src/series/fe/README.md`. Карты FE без подтверждённой геометрии не показываются, сведения и описание читаются из статьи гонки; похожая схема F1 не подставляется.

После изменения общих модулей проверяйте WEC, а также F1 и оболочку FE. Список обязательных проверок и результаты — в `docs/TESTING.md`. Коммит, push и публикацию делает только пользователь.

## Обновление зависимостей

Раз в месяц или по уведомлению о безопасности:

```bash
npm outdated
npm update
npm test && npm run test:e2e && npm run build
```

Мажорные версии (React, Vite, Vitest, Playwright) обновлять по одной, с полным прогоном тестов.

Известное: `npm audit` показывает уязвимость средней важности в `minimatch` внутри ESLint и `typescript-eslint` — только в инструментах разработки, на сайт она не попадает (`npm audit --omit=dev` — 0). Исправится обновлением этих пакетов, когда оно выйдет.
