# Поддержка Racing Hub (этап 7 SDLC)

## Что проверяется автоматически

| Что                                                                                               | Когда                                  | Где                                                          |
| ------------------------------------------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------ |
| Линтер, unit- и E2E-тесты, сборка, публикация на GitHub Pages (только для публичного репозитория) | каждый пуш в `main`                    | `.github/workflows/ci.yml`                                   |
| Живой API Jolpica: доступен ли, не изменился ли формат JSON                                       | каждый понедельник 06:00 UTC и вручную | `.github/workflows/api-health.yml` → `npm run test:contract` |

Если еженедельная проверка падает, в репозитории автоматически открывается issue «API Jolpica: проверка не прошла» со ссылкой на лог. Повторные сбои добавляются в тот же issue комментариями.

Запустить проверку вручную: **Actions → API health check → Run workflow**, или локально:

```bash
npm run test:contract
```

## Если проверка упала

1. Откройте лог из issue и посмотрите, какая проверка не прошла. Сообщения написаны по-русски: например, «маппер отбросил часть этапов — формат календаря изменился».
2. **HTTP 5xx, тайм-аут или сеть** — скорее всего, временный сбой Jolpica. Перезапустите проверку через пару часов. Сайт в это время показывает сохранённые данные с предупреждением.
3. **HTTP 429** — лимиты стали строже. См. раздел «Лимиты».
4. **«Маппер отбросил…» или «не разобраны»** — изменился формат JSON. Сравните ответ API с разбором в `src/series/f1/domain/mappers.ts`, поправьте маппер, добавьте unit-тест на новый формат.
5. Проверьте новости API: https://github.com/jolpica/jolpica-f1 (Releases, Discussions).
6. Закройте issue после исправления.

## Стиль кода

- **ESLint** (`npm run lint`, конфиг `eslint.config.js`): рекомендованные правила JS и TypeScript, правила хуков React, `import type` для типов, строгое сравнение.
- **Prettier** (`npm run format`, конфиг `.prettierrc.json`): одинарные кавычки, точка с запятой, ширина 110, сортировка импортов — сначала React и пакеты, затем модули проекта от дальних к ближним.
- Сгенерированные файлы (`src/series/f1/data/circuits/map.ts`, `shapes/`) форматтер и линтер не трогают.
- CI проверяет и то, и другое: `npm run lint` и `npm run format:check`. Перед коммитом достаточно `npm run format && npm run lint`.

## Стили

Стили разбиты по файлам в `src/styles/`, точка входа — `src/styles/index.css` (подключает части через `@import`, при сборке Vite склеивает их в один файл).

| Файл                                              | Что внутри                                                    |
| ------------------------------------------------- | ------------------------------------------------------------- |
| `01-base.css`                                     | токены, сброс, базовые элементы                               |
| `02-chrome.css`                                   | шапка, раскладка, кнопки, бейджи, состояния загрузки и ошибок |
| `03-pages.css`                                    | главная, календарь, этап, таблицы, профили, график            |
| `04-polish.css`                                   | баннер следующего этапа, подиумные цвета, полоски очков       |
| `05-theme-tokens.css` … `09-theme-responsive.css` | тема v2: токены, шапка, карточки, страницы, адаптив           |
| `10-circuit.css`                                  | схема трассы                                                  |

**Порядок важен:** тема v2 (файлы 05–09) идёт последней и перекрывает правила из 01–04. Поэтому:

- правя элемент, сначала ищите его селектор в 05–09 — скорее всего, итоговый вид задан там;
- не добавляйте новое правило для селектора, у которого уже есть объявления в более позднем файле, — правьте существующее;
- новый блок кладите в файл своей области, новый файл — добавьте в `index.css` в нужное место.

Визуальная проверка: `npm run test:visual` (скриншоты, базлайны зависят от ОС и в репозиторий не кладутся).

## Секреты и .env

Файлы `.env` и `.env.*` в git не попадают (`.gitignore`), шаблон без значений можно хранить как `.env.example`.
Помните: всё, что Vite отдаёт в браузер (`import.meta.env.VITE_*`), видно любому посетителю. Ключи API во фронтенд не кладём — если источник потребует ключ, нужен серверный прокси.

## Лимиты API

Сейчас без токена: 4 запроса/с, 500 запросов/ч. Jolpica предупреждает, что лимиты будут снижаться.
В коде:

- `minIntervalMs` при создании клиента в `src/series/f1/api/jolpica.ts` — минимальная пауза между запросами (сейчас 300 мс ≈ 3,3/с, с запасом до лимита);
- `retries`, `retryBaseMs`, `maxRetryWaitMs` в `src/api/client.ts` — автоповтор при 429 и сбоях;
- `ttlMs` — сколько держать ответ в кэше (по умолчанию 10 минут, задаётся там же, значение по умолчанию — в `src/api/client.ts`). Увеличение кэша — первый способ уменьшить нагрузку;
- самая тяжёлая страница — «График»: по одному запросу на каждый завершённый этап.

Если Jolpica введёт токены, ключ нельзя класть во фронтенд (требование ТЗ) — понадобится серверный прокси.

Сколько запросов тратят страницы (без кэша): профиль пилота — около 10 плюс по одному на каждый сезон его карьеры, сравнение — то же для двух пилотов, «График» — по одному на этап. Итоги **прошедших** сезонов не меняются, поэтому после первой загрузки они берутся из сохранённой в браузере копии без запроса (`immutable` в `src/api/client.ts`); кнопка «Обновить» всё равно идёт к источнику. История команды по сезонам и список всех её пилотов грузятся только по кнопке.

При ответе 429 («слишком много запросов»), сетевой ошибке, таймауте или HTTP 5xx клиент сам повторяет запрос до 3 раз с паузой 1 → 2 → 4 с и придерживает всю очередь. Если источник просит ждать дольше 20 с (исчерпан часовой лимит), повтора нет — показывается ошибка. Сезоны, не загрузившиеся с первого прохода, запрашиваются ещё раз автоматически.

## Схемы трасс

Контуры трасс, длина, число поворотов, направление движения и годы, в которые конфигурация использовалась, — статические данные из [F1DB](https://github.com/f1db/f1db) (CC BY 4.0), не из API.

Устроено так:

- `scripts/build-circuits.mjs` выкачивает YAML и SVG из F1DB и пишет `src/series/f1/data/circuits/map.ts` (Jolpica `circuitId` → slug F1DB) и `src/series/f1/data/circuits/shapes/<slug>.ts` — по файлу на трассу, в каждом все её конфигурации с годами (`eras: [[1997, 2009], …]`, `9999` означает «по сей день»).
- `loadCircuit(circuitId, season)` подтягивает нужный файл через `import.meta.glob` (каждая трасса — отдельный чанк 1–12 КБ) и возвращает конфигурацию, действовавшую в этом сезоне.
- Нет трассы в маппинге, нет конфигурации на этот год или год подходит сразу к нескольким — блок «Схема трассы» не показывается вовсе.

Добавить трассу: строку `'jolpica_id': 'f1db-slug'` в `MAP`, затем

```bash
node scripts/build-circuits.mjs
npm test && npm run build
```

`src/series/f1/components/CircuitMap.test.tsx` проверяет, что геометрия есть для всех трасс сезона и что для разных сезонов выбираются разные конфигурации (Монца 1950 / 1955 / 2026, Сильверстоун 1998 / 2012).

### Чего нет и почему

**Номера поворотов и сектора.** В открытых источниках с явной лицензией их нет: официальные схемы Formula 1 закрыты, F1DB даёт только контур и число поворотов, GeoJSON-наборы bacinger и TUMFTM — только геометрию.

Пробовали выводить из геометрии: считали знаковую кривизну вдоль контура (2400 точек, несколько окон сглаживания и порогов) и выделяли участки поворота. Совпадения с официальным числом — 42 из 158 конфигураций в лучшем наборе параметров, а на крупных трассах детектор ошибается вдвое: Монца 22 против 11, Сильверстоун 36 против 18, Спа 38 против 19, Монако 44 против 19. Это шум рисованной геометрии. Сектора «по третям круга» тоже были бы выдумкой: границы S1/S2/S3 у каждой трассы свои.

Чтобы это появилось, нужен выверенный справочник координат поворотов (ручная разметка по официальным схемам либо источник с явной лицензией) и поле под него в `CircuitLayout`. До этого блок сознательно остаётся без номеров.

**Трассы, которых нет в F1DB** (например, Сочи), схему не показывают — источника геометрии для них нет.

## Исправления результатов

Источник сам обновляет результаты после протестов и штрафов. Приложение подхватывает изменения максимум через 10 минут (кэш) или сразу по кнопке «Обновить».
Раз в несколько этапов повторяйте сверку с formula1.com, как описано в `docs/TESTING.md`.

## Ошибки от пользователей

Принимаются через GitHub Issues. При разборе: какой сезон и страница, что показано на сайте и что ожидалось, совпадает ли это с ответом API (ссылка «Источник» под каждым блоком данных).

## Флаги

`src/lib/flags.ts` сопоставляет национальность («British») и страну этапа («UK») с флагом из `flag-icons` (MIT). Подключены только нужные флаги. Если у источника появится новая национальность или страна, добавьте строку в таблицу — без неё флаг просто не показывается. Для исторических государств (ГДР, Родезия) флага нет намеренно.

## Логотипы команд

У каждой из 11 команд сезона 2026 показывается эмблема в круге цвета команды (`public/logos/`). Это не полный логотип, а только знак, вырезанный из него: у SVG заменён `viewBox`, PNG обрезаны. Как эмблема ложится на круг, задаёт поле `tone` в `src/series/f1/data/logos.ts`: `white` — белый силуэт, `invert` — инверсия с сохранением деталей, `color` — как есть.

Источники: Wikimedia Commons — Mercedes, Alpine, Audi, Haas, McLaren (Speedmark) — общественное достояние; Williams (монограмма) — CC BY-SA 4.0, автор DJClements. Английская Википедия, несвободные файлы (fair use) — Ferrari, Red Bull, Racing Bulls, Aston Martin, Cadillac. Все эмблемы — товарные знаки владельцев и показываются только для обозначения команды на некоммерческом фан-сайте. Если правообладатель попросит убрать файл, удалите его и строку в `logos.ts`.

Новая эмблема: файл в `public/logos/` плюс строка в `logos.ts` (файл, источник, лицензия, правообладатель, `tone`). У команды без эмблемы или если файл не загрузился — значок её цвета с сокращением (MER, FER, RBR).

## Фото пилотов и болидов

Фото берутся с Wikimedia Commons прямо в браузере (`src/api/wikimedia.ts`), их не надо хранить в репозитории. Пилот — главное фото его статьи в английской Википедии (ссылку даёт Jolpica). Команды сезона 2026 — болиды из `src/series/f1/data/carPhotos.ts` (серия с Гран-при Австрии 2026, Lukas Raich, CC BY-SA 4.0). Другие команды — фото из статьи, если это фотография, а не логотип. Используются только файлы с Commons: несвободные файлы Википедии отсекаются. Под фото всегда подписаны автор и лицензия, как требуют CC BY / CC BY-SA. Ответы кэшируются в браузере на 7 дней. Нет фото — нет и пустой рамки.

На новый сезон обновите `carPhotos.ts`: имена файлов новых болидов можно найти в статьях о них в Википедии.

## WEC и Википедия

Данные WEC берутся из английской Википедии (`src/series/wec/api/wikipedia.ts`): у статьи сезона читаются только разделы «Calendar/Schedule» и «Results and standings», статья гонки — целиком. Разбор (`src/series/wec/domain/parse.ts`) ищет колонки по названиям заголовков, поэтому переставленные колонки ему не страшны. Прошедшие сезоны сохраняются в браузере навсегда, текущий — на 10 минут.

Если еженедельная проверка источников (`npm run test:contract`) упала на WEC:

1. Откройте статью сезона и посмотрите, что поменяли: название раздела, заголовки колонок, раскладку таблицы.
2. Скачайте свежий HTML раздела и обновите фикстуры в `src/series/wec/__fixtures__/` (это урезанные настоящие статьи).
3. Поправьте разбор так, чтобы проходили и старые, и новые фикстуры, — старые сезоны в Википедии не переписывают.

Новый сезон появляется сам: список сезонов (`src/series/wec/data/seasons.ts`) доходит до текущего года.

## Обновление зависимостей

Раз в месяц или по уведомлению о безопасности:

```bash
npm outdated
npm update
npm test && npm run test:e2e && npm run build
```

Мажорные версии (React, Vite, Vitest, Playwright) обновлять по одной, с полным прогоном тестов.

Известное: `npm audit` показывает уязвимость средней важности в `minimatch` внутри ESLint и `typescript-eslint` — только в инструментах разработки, на сайт она не попадает (`npm audit --omit=dev` — 0). Исправится обновлением этих пакетов, когда оно выйдет.
