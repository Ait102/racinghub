## Проверки этапа 2 WEC

- Настоящие HTML-фикстуры: Буэми, Кобаяси, Toyota Racing GmbH, AF Corse, история Спа; заявки 2012, 2019–20 и 2026. Проверены суперсезоны, `rowspan`, дробные очки, отдельные строки машин, отсутствие таблиц и исключение других чемпионатов.
- Счётчики: текущий титул не засчитывается; места в классе Ле-Мана читаются из Class Pos., общие места WEC не используются для статистики класса. Неизвестные значения не подменяются нулём.
- API: редирект на каноническую статью, один запрос истории, повторное чтение из кэша, обновление после 10 минут даже с `immutable` в опциях старого сезона, запрет недопустимых названий до запроса.
- E2E: новые пункты меню, заявки до результатов, поиск, переходы из протокола и календаря, история команды, смена сезона внутри профиля, свободное фото с подписью, отсутствующая статья, ошибка и повтор, мобильная ширина и Enter по ссылке. Ссылки календаря не вложены и не перекрываются карточками.
- Добавлено 5 визуальных маршрутов: два списка и три профиля, итого 21 страница на 1280 и 375 px. Эталоны остаются локальными.
- Для трёх длинных профилей WEC снимается первый экран, остальные страницы снимаются целиком. Полностраничный захват истории Toyota зависал в Windows Chromium даже при тайм-ауте 60 секунд. Прямой снимок профиля пилота просмотрен вручную; строки истории, значения и переходы проверяют unit/E2E. Снимки первого экрана не доказывают внешний вид всех строк истории ниже сгиба.
- На Windows полный unit-прогон выполнен с `npm test -- --maxWorkers=2`: параллельный старт множества jsdom расходует память; тяжёлые тесты настоящих таблиц имеют локальный тайм-аут 20 секунд.

**Живой контракт:** все 8 проверок Википедии проходят. В общем прогоне 13/14: существующая проверка F1 «результаты гонки разбираются без потерь» получает от Jolpica пустой протокол. Отдельный запрос подтвердил: зачёт сезона 2026 указывает этап 19, `/2026/19/results/` возвращает `total: 0`. Маппер и контракт F1 не менялись. Это ограничение текущей публикации источника, не зелёный общий контракт; повторить после появления результатов.

## Найдено и исправлено в ходе тестирования

1. Зона UTC показывалась как «UTC+0» → теперь «UTC».
2. Ссылка «Перейти к содержимому» была недоступна: при загрузке фокус сразу ставился на основной блок, а `#main` с HashRouter вёл на несуществующую страницу. Исправлено.
3. Браузер не даёт прочитать `Retry-After`, потому что Jolpica не открывает этот заголовок через CORS. Приложение в этом случае пишет «Повторите немного позже»; тест закрепляет это поведение.

## Скриншотные проверки

Визуальная регрессия вынесена из обычного прогона: базлайны зависят от ОС и установленных шрифтов, поэтому в CI их нет.

```bash
npm run test:visual            # сравнить с базлайнами (21 страница × 2 ширины)
npm run test:visual -- --update  # перезаписать базлайны после осознанного изменения вёрстки
```

Снимки лежат в `e2e/visual.spec.ts-snapshots/` и в git не попадают. Перед снимком страница ждёт `networkidle`, загрузку шрифтов, картинок и фото, плюс 1,2 с; включён режим «уменьшить движение», анимации отключены — так снимок не зависит от момента.

## Как повторить

```bash
npm test
npm run test:e2e
```

Визуальный прогон 02.11.2026: `npx playwright test --config playwright.visual.config.ts --update-snapshots --workers=1` — 1/1, 42 снимка созданы или проверены. Это обновление эталонов после изменения интерфейса; отдельный повторный прогон сравнения с новыми эталонами не выполнялся. Вручную просмотрены профиль пилота на двух ширинах и профиль команды на компьютере.
